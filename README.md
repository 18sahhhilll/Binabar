# Binabar

Binabar is a web guessing game for Indian hip hop (DHH) culture. Players listen to a short instrumental beat clip (10 to 15 seconds) and guess the track. The site is built with Django, vanilla JavaScript and plain modern CSS.

---

## 1. Local Setup

### Requirements
- Python 3.12 or newer
- Virtual environment tool (`venv`)
- Git

### Installation Steps

1. Clone or navigate to the repository directory:
   ```bash
   cd c:\Projects\Binabar
   ```

2. Create and activate a virtual environment:
   - On Windows (PowerShell):
     ```powershell
     python -m venv venv
     .\venv\Scripts\Activate.ps1
     ```
   - On macOS/Linux:
     ```bash
     python3 -m venv venv
     source venv/bin/activate
     ```

3. Install project dependencies:
   ```bash
   pip install -r requirements.txt
   ```

4. Configure your environment file:
   Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
   Generate a secure Django secret key and update `SECRET_KEY` in `.env`.

5. Run database migrations:
   ```bash
   python manage.py migrate
   ```

6. Collect static assets:
   ```bash
   python manage.py collectstatic --noinput
   ```

7. Run the development server:
   ```bash
   python manage.py runserver
   ```
   Open `http://localhost:8000` in your browser.

## 2. Environment Variables

Configure these variables in your `.env` file or hosting provider dashboard:

| Variable | Description | Default in Development |
| :--- | :--- | :--- |
| `SECRET_KEY` | Secret key for cryptographic signing | dev-insecure-key |
| `DEBUG` | Enable debug mode (`True` locally, `False` in production) | `True` |
| `ALLOWED_HOSTS` | Comma-separated list of valid hostnames | `localhost,127.0.0.1` |
| `ADMIN_URL` | Private URL path for Django admin (e.g. `secret-booth/`) | `secret-admin/` |
| `DATABASE_URL` | Database connection string (PostgreSQL in production) | Empty (uses SQLite) |
| `R2_ACCOUNT_ID` | Cloudflare account ID | Empty |
| `R2_ACCESS_KEY_ID` | Cloudflare R2 access key ID | Empty |
| `R2_SECRET_ACCESS_KEY`| Cloudflare R2 secret access key | Empty |
| `R2_BUCKET_NAME` | Cloudflare R2 bucket name | `binabar-audio` |
| `R2_CUSTOM_DOMAIN` | Optional custom domain for R2 audio bucket | Empty |
| `CSRF_TRUSTED_ORIGINS`| Comma-separated list of trusted origins | `http://localhost:8000` |
| `CONTACT_EMAIL` | Public contact and takedown email address | `hello@example.com` |

## 3. Creating the Superuser

To manage songs, you need an admin account:

```bash
python manage.py createsuperuser
```
Follow the prompts to enter your username, email, and password.

---

## 4. Turning On Two-Factor Authentication (TOTP)

Admin login is secured with two-factor authentication (TOTP) using an authenticator app (Google Authenticator, 1Password, or Bitwarden).

1. Start your local server and log in to the admin URL configured in `ADMIN_URL` (for example: `http://localhost:8000/secret-admin/`).
2. After logging in with your superuser credentials, navigate to the two-factor setup page:
   `http://localhost:8000/account/two_factor/setup/`
3. Scan the QR code displayed on the screen using your authenticator app.
4. Enter the 6-digit numeric token generated by your app to verify.
5. Save your backup emergency tokens in a secure password manager.
6. Once configured, every subsequent login to the admin will require your password followed by the one-time TOTP token.
7. Brute-force protection is enforced by `django-axes`. Repeated failed attempts result in account lockout.

## 5. Setting Up Cloudflare R2 for Audio Storage

In production, audio clips are served from Cloudflare R2 via signed URLs rather than permanent public links:

1. Sign in to your Cloudflare Dashboard and select **R2 Object Storage**.
2. Click **Create Bucket** and name it `binabar-audio` (or your preferred bucket name).
3. Under **Manage R2 API Tokens**, create a new token with **Object Read & Write** permissions for your bucket.
4. Note the:
   - Account ID
   - Access Key ID
   - Secret Access Key
5. Enter these values into your production environment variables:
   - `R2_ACCOUNT_ID`
   - `R2_ACCESS_KEY_ID`
   - `R2_SECRET_ACCESS_KEY`
   - `R2_BUCKET_NAME`
6. When `DEBUG=False` and these variables are present, Django automatically uses `storages.backends.s3boto3.S3Boto3Storage` to upload files with random UUID names and generate expiring signed URLs.

## 6. Deploying to Render

This repository includes a `render.yaml` blueprint for one-click setup of both the Web Service and Managed PostgreSQL Database.

1. Create an account on [Render](https://render.com).
2. Connect your Git repository containing the Binabar source code.
3. In the Render Dashboard, click **New +** and select **Blueprint**.
4. Select your repository. Render will automatically detect `render.yaml`.
5. Provide the required environment variables:
   - `ADMIN_URL`: your secret custom admin path (e.g. `gully-panel-91/`)
   - `CONTACT_EMAIL`: your official contact email
   - `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`: your Cloudflare credentials
   - `CSRF_TRUSTED_ORIGINS`: `https://your-service-name.onrender.com`
6. Click **Apply**. Render will provision PostgreSQL, install packages, run database migrations, collect static files, and start Gunicorn.
7. After the service is live, use the Render Shell tab to run:
   ```bash
   python manage.py createsuperuser
   ```
8. Set up two-factor authentication via the setup URL.

## 7. How to Add Your First Song

1. Log in to your private admin URL (e.g. `http://localhost:8000/secret-admin/`).
2. Click on **Songs** -> **Add Song**.
3. Fill in the **Song Info** section:
   - Title (e.g. `Kohinoor`)
   - Artist (e.g. `DIVINE`)
   - Artists (comma-separated list for collaborations, e.g. `DIVINE`)
   - Year (e.g. `2019`)
   - Language (e.g. `Hindi`)
4. Fill in the **Credits** section:
   - Producers (REQUIRED, e.g. `Phenom`)
   - Label (REQUIRED, e.g. `Gully Gang / Mass Appeal India`)
5. Fill in the **Audio** section:
   - Choose `Upload` or `YouTube`.
   - If Upload: select an MP3, M4A or WAV audio file (maximum 15 MB).
   - If YouTube: paste the YouTube URL in the YouTube ID field. The ID will be automatically extracted.
   - Enter `Start seconds` and `End seconds`. Verify the clip length is between 8 and 20 seconds.
6. Review **Hints and accepted answers**:
   - The hints auto-fill from the primary fields (artist initial, year, language).
   - Click "Suggest accepted answers from title" to populate accepted spellings.
7. Fill in **Rights and status**:
   - Source URL (HTTPS official link to song or music video).
   - Permission status (`none`, `requested`, or `granted`).
   - Check the **Verified** box once you have confirmed all credits are accurate.
   - Set status to **Published**.
   *(Note: Publishing is blocked if producers, label, source URL, audio, or the verified checkbox is missing).*
8. Click **Save**. The song will immediately be available in the game and on the `/credits` page.
